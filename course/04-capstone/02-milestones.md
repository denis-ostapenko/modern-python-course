# Capstone milestones

Each milestone ends in an observable result. Record active working time separately from time waiting for a reviewer.

1. **Problem and contract:** choose a brief, three journeys, data fields and location. Write invalid-input and missing-file behavior.
2. **Independent vertical behavior:** implement one complete input-to-result behavior without generated source. Add a focused test and explain the return path.
3. **Domain core:** implement validation, filtering and grouped summary. Empty input works. Domain tests do not require terminal interaction.
4. **Persistence:** demonstrate a JSON round trip, Unicode data, a missing file and damaged input preserved after a failure.
5. **Interface:** test help, success, invalid arguments, error output and exit status. Document option order.
6. **Agent proposal:** checkpoint Git, define one bounded issue, review a live or stored proposal, retain only justified changes and demonstrate recovery.
7. **Collaboration:** complete a live review or the local two-branch conflict simulation. Record the route honestly. A CI run and a human review are different evidence.
8. **Clean handoff:** extract or clone into a fresh folder, reproduce the checks, demonstrate three commands, and verify README recovery instructions.

If a milestone stalls, reduce the next change. Start with one record, then empty input, then multiple records. Use a new work folder for experiments. Optional features begin after the core evidence is complete.
